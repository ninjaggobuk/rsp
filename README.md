# RSP — 가위바위보 원정대

실제 동네를 걸어다니며 하는 보드게임의 **밸런스 분석기 + 브라우저판**.

> **원정대**(다수)는 제한시간 안에 목적지에 도달해야 하고, **쉐도우**(소수)는 그걸 막는다.
> 두 팀은 한 덩어리로 움직이고, 갈림길마다 전원이 가위바위보를 해서
> **상대 팀이 전멸하면** 그 팀이 방향을 정한다. 횡단보도도 갈림길로 센다.

🎮 **[브라우저에서 플레이](https://ninjaggobuk.github.io/rsp/)** — 계정 없이 바로 열립니다

| | |
|---|---|
| 지도 | 일반(OSM) · 위성(Esri) · 지형 · **카카오맵** |
| 로비 | 최대 10명, 진영 간 이동, AI 봇 추가, 닉네임 |
| 아이템 | 팀별 분배 + 사용 투표(만장일치 / 과반 / 방장 / 없음) |
| 채팅 | 전체 · 팀 (팀 채팅은 시작 후) |
| AI 쉐도우 | 가치반복을 브라우저에서 직접 돌려 실제로 최악의 길을 고른다 |

멀티플레이(방 코드·실시간 동기화) 설계는 [docs/MULTIPLAYER.md](docs/MULTIPLAYER.md).
통신 경계(`NET`)는 이미 들어가 있고 지금은 로컬 모드로 돈다.

## 왜 만들었나

실제로 6판을 해봤더니 **원정대 1승 5패**. 밸런스를 잡으려면 "갈림길 한 번 지면
얼마나 손해인가"를 알아야 하는데, 손으로는 셀 수 없다. 그래서 실제 지도 위에서
계산했다.

## 결론

### 진단 — 왜 원정대가 계속 졌나

| 원인 | 내용 |
|---|---|
| 연속 승리 요구 | 최단 경로 갈림길 9개를 한 번도 안 지고 가려면 (2/3)⁹ = **2.6%** |
| 악순환 | 지면 낯선 골목으로 들어가 갈림길이 9개 → **25개**로 늘어난다 |
| 긴 꼬리 | 지는 비용 중앙값 20분, 최악 **170분**. 한 방에 끝나는 갈림길이 실재한다 |
| 쉐도우 아이템 | 쉐도우에게 3종 세트를 주면 원정대가 **13~25%** 로 붕괴한다 |

### 권고 — 공릉 일대 4:2 기준

> **아이템: 재도전권 원정대 1개 / 쉐도우 1개. 그 외는 주지 않는다.**

공릉 일대 임의 지점쌍 24개에서 **중앙값 49.7%**, 루트의 75%가 40~60%에 들어온다.

- **재도전권이 가장 강하다** — 무조건승리는 3번 중 2번 어차피 이길 자리에 버려지지만,
  재도전권은 **실제로 졌을 때만 소모**된다. 같은 1개로 갈림길 3개분의 보험이 된다.
- **직진권은 분산 증폭기다** — 직진이 마침 옳은 방향일 때만 작동해서, 루트에 따라
  무용지물이 되거나 강력해진다. 넣으면 루트 간 편차가 35 → 50%p 로 커진다.
- **쉐도우는 2명까지.** 3명 이상이 서로 다른 기호로 갈라 내면 매 라운드 세 기호가
  다 나와 **무승부가 영원히 반복**된다. 규칙 구멍이다.

### 한계 — 아이템으로 못 고치는 것

아이템은 **중앙값만 옮기고 루트 간 30%p 격차는 못 줄인다.** 같은 거리(도보 25~30분)
라도 지점쌍에 따라 원정대 승률이 28%~57% 로 갈린다.

지형 특징으로 예측해보려 했으나 실패했다 — 가장 강한 지표(갈림길 수)도 r = −0.40,
변동의 16%만 설명한다. **눈으로 판단하는 규칙은 만들 수 없다.** 그래서 루트를
하나씩 재는 도구(`check_route.py`)를 만들었다.

## 쓰는 법

### 루트가 공정한지 확인

```bash
python src/check_route.py --from "37.63150,127.07770" --to "37.61900,127.06900"
```

좌표는 네이버 지도에서 우클릭하면 나온다. **90분 도착률 45~55%** 면 공정한 루트다.
치명적 갈림길(지면 손해가 큰 교차로)의 위치와 지도 링크도 같이 나온다.

### 밸런스 다시 계산

```bash
python src/tune_gongneung.py      # 공릉 임의 루트 24개 평균으로 아이템 개수 탐색
python src/search_42.py           # 4:2 에서 가장 균형·안정적인 분배 찾기
python src/probe_rps_balance.py   # 인원 구성별 갈림길 승률 (이론 vs 시뮬)
```

### 게임 다시 빌드

```bash
python src/export_map.py          # OSM 그래프 -> web/gongneung.json
python src/build_web.py           # 템플릿 + 데이터 -> docs/index.html
```

## 환경

`rsp` conda 환경이 필요하다 (osmnx, geopandas, networkx, matplotlib).

```bash
conda create -n rsp -c conda-forge -y python=3.12 osmnx matplotlib networkx scipy
```

> ⚠ Windows 에서 conda 환경을 activate 없이 `envs/rsp/python.exe` 로 직접 부르면
> matplotlib 이 그리는 시점에 DLL 을 못 찾아 **traceback 없이 프로세스가 죽는다**
> (`0xc06d007f`). `src/_envpath.py` 가 PATH 를 스스로 채워 이걸 막는다.

## 코드 구조

| 파일 | 역할 |
|---|---|
| `src/rps.py` | 다인 가위바위보 판정 (탈락식) |
| `src/rsp_map.py` | OSM 보행망 다운로드·캐시·측정 |
| `src/solve_items.py` | 규칙 엔진 + 가치반복 + 아이템 시뮬 |
| `src/check_route.py` | **루트 체커** — 특정 지점쌍이 공정한지 |
| `src/tune_gongneung.py` | 공릉 평균에 맞춘 아이템 튜닝 |
| `src/route_features.py` | 난이도를 예측하는 지형 특징 탐색 (결과: 실패) |
| `src/export_map.py` · `build_web.py` | 브라우저판 빌드 |
| `web/game.template.html` | 게임 원본 (지도 데이터는 빌드 시 주입) |
| `docs/index.html` | 빌드 결과 — GitHub Pages 가 서빙한다 |
| `docs/config.js` | 지도·Firebase 키. 재빌드 없이 바꿀 수 있다 |

### 키에 대해

`docs/config.js` 의 카카오 **JavaScript 키**는 페이지 소스에 그대로 실리는 공개
식별자다. 보안은 카카오 콘솔의 **도메인 제한**으로 건다 — 다른 도메인에서는
쓸 수 없다. REST API 키와 Admin 키는 진짜 비밀이므로 여기 넣지 않는다.
Firebase 웹 설정도 같은 성격이고, 보안은 Realtime Database 규칙으로 건다.

## 모델의 한계

- **쉐도우 AI 가 전지적이다.** 동네 전체의 정답표를 알고 매번 수학적 최악을 고른다.
  실제 사람은 그만큼 못 하므로 **모든 승률은 원정대 기준 하한**이다.
  (다만 실측 6판 1승 = 16.7% 와 모델 13.2% 가 맞아떨어지긴 했다. n=6 이라 약한 증거다.)
- **쉐도우가 원정대의 마지막 아이템을 노려 아껴두는 수싸움**은 모델에 없다.
  지금은 양 팀이 "손해가 40분 이상이면 쓴다"로만 판단한다.
- 공릉 일대에서만 검증했다.
